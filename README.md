# 🍔 McRadar by Nico · 麦麦雷达

**今天吃什么？让 AI 给你开个麦麦盲盒！**

一个基于麦当劳中国官方 MCP 的 AI 协作点餐 Skill。告诉 AI 你的预算、人数、口味和忌口，让它帮你探索菜单、组合餐食，给今天这顿麦当劳制造一点惊喜。你可以继续和 AI 商量、调整方案，满意后再明确授权下单。

**从「不知道吃什么」到真正点好一顿饭。**

> 🚧 **Beta 测试中**：项目已完成首次真实订单验证，正在进行外部用户测试。当前主要通过麦当劳官方点餐渠道工作，不提供跨平台比价或全网最低价保证。

## 🎁 普通用户：开一个麦麦盲盒

不知道吃什么的时候，不必从头翻菜单。

试着告诉 AI：

> 我有 40 块钱，想吃麦当劳，但今天不想自己选。不要鱼，其他随你发挥，给我开个盲盒！

或者：

> 两个人吃，预算 80 块，想要有汉堡、有小食，最好还能有点惊喜。

AI 会根据你的要求和官方渠道可用的餐品信息，探索合适的组合。

你可以选择保留惊喜，也可以让 AI 展示候选餐品，继续讨论、替换和调整。

### 一顿麦麦盲盒是怎么诞生的？

1. **告诉 AI 你的想法**：预算、人数、口味、忌口，或者干脆说「随便来点惊喜」。
2. **一起探索餐食组合**：AI 查询可用菜单，结合你的要求提出方案。
3. **调整到满意为止**：不喜欢某种餐品？想换个搭配？直接和 AI 聊。
4. **确认真实订单**：下单前查看订单摘要、金额和配送等信息，由你明确授权。
5. **自己完成支付，等待开吃**：AI 协助完成受支持的下单步骤，付款由用户自行操作。

**AI 可以提出建议，但不会因为你说了「想吃什么」就自动替你提交真实订单。**

### 还能怎么玩？

**🎲 惊喜盲盒**
「今天让你决定，但不要给我点鱼。」

**👥 多人餐食**
「我们三个人吃，预算 120 元，尽量照顾不同口味。」

**🍔 指定偏好**
「想吃牛肉汉堡，其他搭配给我一点惊喜。」

**💬 反复协商**
「这套我不喜欢，换一种风格试试。」

以上是自然语言玩法示例；实际餐品、价格和可执行操作以当前门店、官方 MCP 能力及订单校验结果为准。

## 🛠️ 技术用户：让 Agent 真正参与点餐

McRadar by Nico 不只是一个生成随机菜单的提示词。

它通过 Skill 定义 Agent 的点餐工作流，调用麦当劳中国官方 MCP 获取业务信息，并在明确的用户授权边界内推进真实订单。

### 技术组成

- **Skill**（`SKILL.md`）：定义对话行为、盲盒生成流程、订单确认状态机与安全红线。
- **麦当劳官方 MCP**：提供受支持的菜单、算价、优惠、订单等能力（`https://mcp.mcd.cn`，Streamable HTTP）。
- **Python 脚本**（`scripts/`）：零第三方依赖，只用标准库。CLI 入口 `mcd_radar.py` 提供 37 个子命令，`scripts/mcdradar/` 下为 16 个功能模块（金额换算、菜单规范化、偏好过滤、组合生成、套餐换项、券匹配、活动解析、订单闸门、领券闸门等）。
- **自动化测试**（`tests/`）：11 个测试套件、253 条用例，覆盖选品、预算、订单处理及关键安全行为。

### 调用架构（重要）

**MCP 调用由 AI 客户端（宿主）负责；Python 脚本只做数据处理与状态校验，不实现 MCP 客户端，也不负责 MCP 认证。**

```
AI 客户端 ──调用 MCP 工具──> 麦当劳官方 MCP
     │                            │
     │<───────── JSON 返回 ───────┘
     │
     ├── 把返回交给 scripts/mcd_radar.py（--json / --file / stdin）
     │      脚本负责：单位换算、过滤、组合、券匹配、摘要、闸门校验
     │
     └── 按脚本返回的 allowed / ok 决定是否执行真实写操作
```

这样划分的好处：**Python 脚本不负责 MCP 认证，也不主动读取或保存 Token；认证信息由 AI 客户端管理。** 脚本因此既不受 MCP 协议版本变化影响，也可以在完全不联网的前提下被自动化测试覆盖。

### 为什么要做成 Skill？

因为「帮我点一顿麦当劳」并不是单次问答。

Agent 需要理解需求、查询实时业务数据、处理约束、提出组合、接受用户修改，并且在真正产生交易之前停下来等待授权。

麦麦雷达尝试把这些步骤组织成一个可复用、可验证的协作流程——尤其是下单前后的一整套闸门：**实时算价 → 算价覆盖校验 → 一次完整摘要 → 用户明确确认 → 提交前四重复核**。

### 工程验证

当前 Beta 阶段已完成：

- 首次真实麦当劳订单验证（下单 → 支付 → 配餐中，全链路走通）。
- **253 项自动化测试通过（11 套件）**，且测试全程不触发真实交易。
- 外部用户测试准备及发布前隐私清洗。
- 订单提交与支付授权相关的安全约束（确认状态机、算价覆盖校验、写操作不重试）。

自动化测试通过不代表所有地区、门店、客户端和优惠场景都已得到真实环境验证。

## 📦 安装与配置

> 以下步骤以 **Windows + WorkBuddy** 为已实测基准；其他环境的支持程度见下方「客户端兼容性」。

### 前置条件

- 可用的 **AI Agent 客户端，且支持 MCP**（麦麦雷达自己不联网，靠客户端调用 MCP）。
- **Python 3.10 及以上**（脚本仅用标准库，无需安装任何第三方包）。
- 麦当劳中国官方 MCP 所需的**个人 Token**（需你本人申请）。
- 使用真实下单功能时所需的个人账号及支付环境。

### 步骤 1 · 安装 Skill

把仓库下载到本地，在仓库根目录执行：

```bash
# 同步到 WorkBuddy 用户级 Skill 目录（~/.workbuddy/skills/mcd-radar/）
python tools/install_skill.py

# 只检查两份是否一致，不做修改
python tools/install_skill.py --check

# 卸载安装副本（保留仓库源码）
python tools/install_skill.py --remove
```

同步方向恒为「仓库 → 用户目录」，不会反向覆盖；改完代码重新运行即可。若你的客户端不是 WorkBuddy，也可以用 `--target` 指定目标目录，或手动把 `SKILL.md` 与 `scripts/` 复制到该客户端的 skills 目录下，目录名保持 `mcd-radar`。

### 步骤 2 · 验证安装（只读、不联网、不下单）

```bash
python scripts/mcd_radar.py selftest
```

看到类似输出即为脚本层安装成功：

```json
{ "ok": true, "now": "....", "version": "0.1.0" }
```

### 步骤 3 · 配置麦当劳官方 MCP（Token 需你本人获取）

**① 获取 Token（必须你本人操作）**

1. 打开官方控制台 <https://open.mcd.cn/mcp>，用**手机号登录**并完成验证。
2. 进入【控制台】→【激活】，阅读并同意《使用条款》与《麦当劳 MCP 服务规则》，申请 MCP Token。
3. Token 生成后自行妥善保管。

**② 关键区别：仓库模板 vs 你本地的配置**

| | 仓库中的模板 | 你本地的实际配置 |
|---|---|---|
| 文件 | [`mcp-config.example.json`](./mcp-config.example.json) | 由你的 AI 客户端管理（例如客户端内的 MCP 配置项） |
| Token | **只有占位符 `<你的_MCP_TOKEN>`**，任何时候都不含真实凭证 | 填入你自己领取的 Token |
| 能否直接连上 | **不能**——模板只是结构示例 | 配置正确后即可连接 |

模板内容：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": { "Authorization": "Bearer <你的_MCP_TOKEN>" }
    }
  }
}
```

**③ 你需要手动替换模板里的占位符**

> **只修改 `<你的_MCP_TOKEN>` 为你拿到的 TOKEN，不要删除前面的 `Bearer`。**

- `<你的_MCP_TOKEN>` 是**占位符**：它不是可用的 Token，也不是环境变量名，请整段替换成你自己从官方控制台复制的 Token。
- `Bearer` 是 HTTP 鉴权方案标识，**必须保留**，正确结果形如 `Bearer eyJhbGciOi...`。
- 本仓库的模板**不依赖任何自动展开能力**，复制后按上面一条手工替换即可。
- 不同客户端的 MCP 配置入口与字段命名可能不同；本项目的已实测客户端是 WorkBuddy，其他客户端请以各自官方文档为准。

> ⚠️ **不要把「复制仓库里的占位符」当成能直接连上的配置。** 未替换占位符前，鉴权一定失败。
> ⚠️ 若你已有其他 MCP 配置，请**合并** `mcpServers` 中的条目，**不要覆盖**已有内容。
> ⚠️ 仓库中**不含任何真实 Token**；请勿把个人 Token、Cookie 或其他凭证提交到公开仓库，也不要粘贴进 AI 对话。

更多集成细节见 [`MCP_INTEGRATION.md`](./MCP_INTEGRATION.md)。

### 步骤 4 · 开始第一次对话

配置完成后，直接在对话里描述需求即可（不必背命令，AI 会按 `SKILL.md` 执行）。建议一次说清：**预算（含口径）**、**人数**、**就餐方式**（到店自取 / 得来速 / 外卖到家）、**忌口与偏好**、**门店或区域**。

开场白示例：

> 用麦麦雷达帮我点餐。我们 2 个人，预算 36 元，**只算商品价**，不要鱼，饮品要无糖可乐，尽量别甜品。
> 我想试试**预算盲盒**，给我几个差异化的组合看看，先别下单。

## 🔒 真实交易与安全边界

麦麦雷达涉及真实订单，因此安全边界比普通聊天工具更加重要。

- 讨论餐品、选择方案不等于授权下单。
- 真实订单提交前需要用户**明确确认**；下单与领券属写操作，没有明确授权就停在摘要这一步。
- 订单金额、配送及其他费用应在提交前清楚展示。
- **金额只认官方接口的实时算价结果**；菜单价仅用于筛选，不作为应付金额承诺。
- 支付由用户自行完成——麦当劳 MCP 没有任何支付工具，架构上 AI 无法也不会替你付款。
- 对结果不明确的订单提交，不应盲目重复操作：写操作不重试，先只读核对订单状态，确认需要重试时再取得用户的新授权，以免产生重复订单。
- **订单创建成功 ≠ 已支付**；支付状态以用户自身操作为准。
- 优惠券和活动的实际可用性，以官方渠道返回的信息为准；官方限制一单一张券，不承诺「叠加最优」。
- **不做过敏原识别，不承诺过敏安全**：忌口仅基于餐品分类与名称关键词。
- 不把 Token、支付凭证、完整地址、手机号保存到本地状态。

**麦麦雷达不是全网最低价搜索工具。** 它的主要目标是让 AI 协作点餐更有趣、更省心，而不是保证比第三方外卖或团购平台便宜。
